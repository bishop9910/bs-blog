1: # Achero 音乐服务器 — 服务端实现与协议
2: 
3: 本文描述本仓库（Kratos 驱动的 Go 音乐服务器）如何实现 Achero 内置插件
4: `com.achero.musicServer` 的 RPC 协议，并给出部署与验证方法。
5: 
6: > 机器可读的 OpenAPI 3.1 描述见仓库根目录 `openapi.yaml`（`make openapi` 校验）。
7: 
8: ---
9: 
10: ## 1. 传输层
11: 
12: - **端点**：一个固定的 HTTP URL，默认 `http://<host>:8080/rpc`（可用
13:   `music.rpc_path` 修改）。
14: - **方法**：`POST`。
15: - **请求头**：
16:   - `Content-Type: application/json`
17:   - （可选）`Authorization: Bearer <token>`
18: - **请求体**：标准 JSON-RPC 2.0 请求对象。
19: 
20: ```json
21: { "jsonrpc": "2.0", "id": 1, "method": "music.list", "params": { "offset": 0, "limit": 200 } }
22: ```
23: 
24: - **响应体**：标准 JSON-RPC 2.0 响应（成功 `result`，失败 `error`）。
25: 
26: ```json
27: { "jsonrpc": "2.0", "id": 1, "result": { "tracks": [ /* ... */ ] } }
28: ```
29: 
30: ## 2. 鉴权
31: 
32: | 用途 | 方式 | 说明 |
33: | --- | --- | --- |
34: | RPC 元数据调用 | `Authorization: Bearer <token>` 请求头 | `music.token` 非空时强制 |
35: | 音频流 / 封面 | **签名 URL**（`?token=<签名>`） | 见下方签名格式 |
36: 
37: ### 签名 URL
38: 
39: 当 `music.stream_secret`（或回退的 `music.token`）非空时，`music.list` /
40: `music.streamUrl` 返回的 `url`、`coverUrl` 会携带签名令牌：
41: 
42: ```
43: http://host:8080/stream/<id>?token=<expires>:<hex>
44: ```
45: 
46: - `expires`：Unix 秒时间戳，`now + music.token_ttl`。
47: - `hex`：`HMAC-SHA256(secret, "<purpose>:<id>:<expires>")` 的十六进制摘要。
48: - `purpose`：`stream` 或 `cover`，用于绑定令牌用途，防止跨端点重放。
49: - 令牌过期或篡改时，服务端返回 `403 Forbidden`。
50: 
51: > 两个密钥都为空时，URL 不带签名，流与封面完全开放。
52: 
53: ## 3. 方法
54: 
55: ### 3.1 `music.ping`
56: 
57: 参数为空，返回 `{"ok": true}`。
58: 
59: ```json
60: { "jsonrpc": "2.0", "id": 0, "method": "music.ping", "params": {} }
61: → { "jsonrpc": "2.0", "id": 0, "result": { "ok": true } }
62: ```
63: 
64: ### 3.2 `music.list`
65: 
66: | 参数 | 类型 | 必填 | 说明 |
67: | --- | --- | --- | --- |
68: | `offset` | int | 否 | 分页偏移，默认 0 |
69: | `limit` | int | 否 | 每页数量，默认 200 |
70: 
71: 响应 `result` 包含 `tracks`（数组）与 `total`（曲目总数，便于分页）。
72: 
73: ```json
74: {
75:   "jsonrpc": "2.0",
76:   "id": 1,
77:   "result": {
78:     "total": 1,
79:     "tracks": [
80:       {
81:         "id": "3a2c1f9e8b7d6c5a4b3a2c1f",
82:         "title": "海阔天空",
83:         "artist": "Beyond",
84:         "album": "乐与怒",
85:         "durationMs": 324000,
86:         "url": "http://192.168.1.10:8080/stream/3a2c1f9e8b7d6c5a4b3a2c1f?token=...",
87:         "coverUrl": "http://192.168.1.10:8080/cover/3a2c1f9e8b7d6c5a4b3a2c1f?token=...",
88:         "lyrics": "[00:00.00]今天我\n[00:05.00]寒夜里看雪飘过"
89:       }
90:     ]
91:   }
92: }
93: ```
94: 
95: ### 3.3 `music.listAlbums`（可选）
96: 
97: 按专辑浏览。客户端不强制要求实现，失败会自动回退到纯歌曲列表。
98: 
99: | 参数 | 类型 | 必填 | 说明 |
100: | --- | --- | --- | --- |
101: | `offset` | int | 否 | 分页偏移，默认 0 |
102: | `limit` | int | 否 | 每页数量，默认 200 |
103: 
104: 响应 `result` 含 `albums`（数组）与 `total`：
105: 
106: ```json
107: {
108:   "jsonrpc": "2.0",
109:   "id": 1,
110:   "result": {
111:     "total": 1,
112:     "albums": [
113:       { "id": "a1", "name": "乐与怒", "artist": "Beyond", "coverUrl": "...", "songCount": 10, "year": 1993 }
114:     ]
115:   }
116: }
117: ```
118: 
119: ### 3.4 `music.listArtists`（可选）
120: 
121: 按艺术家浏览。客户端不强制要求实现。
122: 
123: | 参数 | 类型 | 必填 | 说明 |
124: | --- | --- | --- | --- |
125: | `offset` | int | 否 | 分页偏移，默认 0 |
126: | `limit` | int | 否 | 每页数量，默认 200 |
127: 
128: 响应 `result` 含 `artists`（数组）与 `total`：
129: 
130: ```json
131: {
132:   "jsonrpc": "2.0",
133:   "id": 1,
134:   "result": {
135:     "total": 1,
136:     "artists": [
137:       { "id": "ar1", "name": "Beyond", "albumCount": 8, "songCount": 96, "coverUrl": "..." }
138:     ]
139:   }
140: }
141: ```
142: 
143: ### 3.5 `music.listSongs`（可选）
144: 
145: 按专辑或艺术家拉取曲目。`albumId` / `artistId` 至少提供其一；同时提供时以服务器
146: 实现为准（本实现会同时满足两者，即取交集）。
147: 
148: | 参数 | 类型 | 必填 | 说明 |
149: | --- | --- | --- | --- |
150: | `albumId` | string | 二选一 | 按专辑拉取曲目 |
151: | `artistId` | string | 二选一 | 按艺术家拉取曲目 |
152: | `offset` | int | 否 | 分页偏移，默认 0 |
153: | `limit` | int | 否 | 每页数量，默认 200 |
154: 
155: 响应曲目结构与 [`music.list`](#32-musiclist) 一致：
156: 
157: ```json
158: { "jsonrpc": "2.0", "id": 1, "result": { "tracks": [ /* ... */ ], "total": 1 } }
159: ```
160: 
161: ### 3.6 `music.streamUrl`
162: 
163: 当 `music.list` 未返回 `url` 时按曲目 id 解析流地址（本实现始终在 list 中返回
164: `url`，此方法作为兜底）。
165: 
166: | 参数 | 类型 | 必填 | 说明 |
167: | --- | --- | --- | --- |
168: | `id` | string | 是 | 曲目 id |
169: 
170: ```json
171: { "jsonrpc": "2.0", "id": 2, "method": "music.streamUrl", "params": { "id": "..." } }
172: → { "jsonrpc": "2.0", "id": 2, "result": { "url": "http://.../stream/...?token=..." } }
173: ```

175: ## 4. 数据结构
176: 
177: ### Track
178: 
179: | 字段 | 类型 | 必填 | 说明 |
180: | --- | --- | --- | --- |
181: | `id` | string | 是 | 曲目唯一 id（相对路径的 SHA-256 前缀，不透明、防目录穿越） |
182: | `title` | string | 是 | 标题（标签缺失时回退为文件名） |
183: | `artist` | string | 否 | 艺术家 |
184: | `album` | string | 否 | 专辑 |
185: | `durationMs` | int | 否 | 时长（毫秒），解析失败时为 0 |
186: | `url` | string | 否 | 流地址（可带签名） |
187: | `coverUrl` | string | 否 | 封面地址（仅内嵌封面存在时返回） |
188: | `lyrics` | string | 否 | 内联 LRC 文本（存在同名 `.lrc` 时返回） |
189: 
190: ### Album
191: 
192: | 字段 | 类型 | 必填 | 说明 |
193: | --- | --- | --- | --- |
194: | `id` | string | 是 | 专辑唯一 id（`sha256(专辑艺术家 + "\0" + 专辑名)` 前缀） |
195: | `name` | string | 是 | 专辑名 |
196: | `artist` | string | 否 | 专辑艺术家（`AlbumArtist` 标签，缺省回退曲目艺术家） |
197: | `coverUrl` | string | 否 | 封面地址（指向代表曲目的封面） |
198: | `songCount` | int | 否 | 曲目数 |
199: | `year` | int | 否 | 发行年份（取自标签，缺失时不返回） |
200: 
201: ### Artist
202: 
203: | 字段 | 类型 | 必填 | 说明 |
204: | --- | --- | --- | --- |
205: | `id` | string | 是 | 艺术家唯一 id（`sha256(艺术家名)` 前缀） |
206: | `name` | string | 是 | 艺术家名 |
207: | `albumCount` | int | 否 | 专辑数 |
208: | `songCount` | int | 否 | 曲目数 |
209: | `coverUrl` | string | 否 | 头像/封面地址（指向代表曲目的封面） |

211: ## 5. 错误处理
212: 
213: 失败返回 JSON-RPC 错误对象；传输层错误（鉴权失败、方法不允许）返回对应 HTTP
214: 状态码。
215: 
216: | 场景 | code | HTTP |
217: | --- | --- | --- |
218: | 请求体不是合法 JSON | `-32700` | 200 |
219: | 请求不合法（缺 `method` / `jsonrpc`） | `-32600` | 200 |
220: | 未知方法 | `-32601` | 200 |
221: | 参数缺失 / 非法 | `-32602` | 200 |
222: | 曲目不存在 | `-32001` | 200 |
223: | 内部错误 | `-32000` | 200 |
224: | 未授权（Bearer 缺失 / 错误） | — | 401 |
225: | 流令牌无效 / 过期 | — | 403 |
226: | 请求方法不允许 | — | 405 |

228: ## 6. 曲目来源与元数据
229: 
230: 服务端启动时递归扫描 `music.music_dir`：
231: 
232: - **索引**：按配置的扩展名收集音频文件，`id = sha256(相对路径)[:24]`，稳定且不泄露
233:   文件系统结构。
234: - **标签**：用 `github.com/dhowden/tag` 读取 `title` / `artist` / `album` /
235:   `album_artist` / `year` 与内嵌封面（ID3v2、MP4、FLAC、Vorbis）。
236: - **专辑/艺术家**：扫描后按标签聚合出 `Album` / `Artist` 视图（供 `listAlbums` /
237:   `listArtists` / `listSongs` 使用）——专辑按「专辑艺术家 + 专辑名」归并，艺术家按
238:   曲目艺术家归并；缺标签时回退为「未知专辑」/「未知艺术家」。专辑/艺术家的封面
239:   取自组内第一首带内嵌封面的曲目。
240: - **时长**：内置解析器按格式计算——
241:   - MP3：Xing/Info VBR 帧数，否则 CBR 估算；
242:   - FLAC：STREAMINFO 总采样数 / 采样率；
243:   - M4A/M4B：`moov/mvhd` 的 timescale 与 duration；
244:   - Ogg/Opus：末页 granule position；
245:   - WAV：`fmt` byte rate 与 `data` 大小。
246:   解析失败时 `durationMs` 为 0（协议中为可选字段）。
247: - **歌词**：同名 `.lrc` 文件（如 `song.mp3` → `song.lrc`）会内联到 `lyrics`；
248:   读取时自动把 GBK/GB2312 编码归一化为 UTF-8。
249: - **JSON 侧车（自定义元数据 / 封面）**：音乐文件旁的**同名 JSON**（`song.mp3` →
250:   `song.json`）可覆盖元数据，**优先级高于音乐文件自身标签**。支持字段：`title` /
251:   `artist` / `album` / `albumArtist` / `year` / `lyrics` / `cover`。其中 `cover`
252:   与 `lyrics` 都**只允许相对路径**（相对 JSON 所在目录），且解析后必须仍在
253:   `music_dir` 内——绝对路径与 `..` 越界都会被拒绝：
254:   - `cover`：指向封面图片文件；
255:   - `lyrics`：以 `.lrc` / `.txt` 结尾时视为指向歌词文件（同样做 GBK 归一化），
256:     否则视为内联 LRC 文本。
257:   JSON 里未填写的字段回退到音乐文件标签。
258: 
259:   ```json
260:   { "title": "海阔天空", "artist": "Beyond", "year": 1993, "cover": "cover.jpg", "lyrics": "lyrics/foo.lrc" }
261:   ```
262: 
263: - **热重载**：`music.watch: true`（默认）时用 fsnotify 监听目录，文件新增/删除/
264:   改名会触发**防抖后的自动重扫**（默认 2 秒内无新事件才重建索引），无需重启；
265:   同时自动为新建的子目录补挂监听。`music.rescan_interval` 作为轮询兜底（对
266:   不支持监听的文件系统/网络挂载更可靠）。两者可同时开启。
267: - **索引原子替换**：重扫会整体重建并原子换入新索引，读取端无阻塞、无需加锁等待。
268: 
269: > 首次扫描需逐个读取标签，超大曲库可能耗时数秒到数十秒；日志会输出
270: > `music library indexed count=…`，热重载时也会输出同样的行确认已刷新。
271: 
272: ## 7. 音频流
273: 
274: `GET /stream/{id}?token=…`（以及 `HEAD`）返回音频字节流：
275: 
276: - 由 `http.ServeContent` 处理，**完整支持 `Range` 请求**（`206 Partial Content`、
277:   `Accept-Ranges: bytes`），保证拖动进度条可用。
278: - `Content-Type` 取自文件扩展名（如 `audio/mpeg`、`audio/flac`）。
279: - 若 `music.token` / `music.stream_secret` 已配置，`token` 缺失或无效返回 `403`。
280: 
281: 封面端点 `GET /cover/{id}?token=…` 返回内嵌封面（`Cache-Control: public`，缓存 1 天）。
282: 
283: ## 8. 配置参考
284: 
285: 见 `configs/config.yaml`，全部项：
286: 
287: | 键 | 类型 | 默认 | 说明 |
288: | --- | --- | --- | --- |
289: | `server.http.addr` | string | `0.0.0.0:8080` | 监听地址 |
290: | `server.http.timeout` | duration | `0s` | 处理器超时；**保持 0**，避免中断流式播放 |
291: | `music.music_dir` | string | `${MUSIC_DIR:./music}` | 扫描目录 |
292: | `music.base_url` | string | `""` | 公网基址 `scheme://host[:port]`；空则按请求推导 |
293: | `music.token` | string | `""` | RPC Bearer 令牌；空 = 不鉴权 |
294: | `music.stream_secret` | string | `""` | 签名密钥；空 = 回退 `token` |
295: | `music.token_ttl` | int64 | `3600` | 签名 URL 有效期（秒） |
296: | `music.rpc_path` | string | `/rpc` | JSON-RPC 路径 |
297: | `music.stream_path` | string | `/stream` | 流路径前缀 |
298: | `music.cover_path` | string | `/cover` | 封面路径前缀 |
299: | `music.extensions` | []string | 内置列表 | 索引扩展名 |
300: | `music.rescan_interval` | duration | `0s` | 轮询重扫间隔，0 关闭 |
301: | `music.watch` | bool | `true` | 用 fsnotify 监听目录，文件增删/改名时自动重扫（热重载） |
302: 
303: 环境变量：配置支持 `${VAR:default}` 语法，且 `KRATOS_` 前缀的环境变量可覆盖
304: （如 `KRATOS_MUSIC_TOKEN`）。

306: ## 9. 部署
307: 
308: ### 本地
309: 
310: ```bash

320: 
321: ```bash
322: docker build -t acheron-music-server .
323: docker run --rm -p 8080:8080 \
324:   -v "$PWD/configs:/data/conf" \

329: 
330: ### 验证（curl）
331: 
332: ```bash
333: # 健康检查
334: curl -s -X POST http://localhost:8080/rpc \
335:   -H 'Content-Type: application/json' \
336:   -d '{"jsonrpc":"2.0","id":0,"method":"music.ping","params":{}}'
337: 
338: # 拉取列表
339: curl -s -X POST http://localhost:8080/rpc \
340:   -H 'Content-Type: application/json' \
341:   -d '{"jsonrpc":"2.0","id":1,"method":"music.list","params":{"offset":0,"limit":10}}'
342: 
343: # 拉取专辑 / 艺术家 / 按专辑拉歌（可选方法）
344: curl -s -X POST http://localhost:8080/rpc \
345:   -H 'Content-Type: application/json' \
346:   -d '{"jsonrpc":"2.0","id":1,"method":"music.listAlbums","params":{}}'
347: curl -s -X POST http://localhost:8080/rpc \
348:   -H 'Content-Type: application/json' \
349:   -d '{"jsonrpc":"2.0","id":1,"method":"music.listArtists","params":{}}'
350: curl -s -X POST http://localhost:8080/rpc \
351:   -H 'Content-Type: application/json' \
352:   -d '{"jsonrpc":"2.0","id":1,"method":"music.listSongs","params":{"albumId":"<album-id>"}}'
353: 
354: # 带鉴权（配置 music.token 后）
355: curl -s -X POST http://localhost:8080/rpc \
356:   -H 'Content-Type: application/json' \
357:   -H 'Authorization: Bearer <token>' \
358:   -d '{"jsonrpc":"2.0","id":1,"method":"music.list","params":{}}'
359: ```

361: ## 10. 参考服务端要点
362: 
363: 本实现即是一个可直接使用的参考服务端。若需要自研，最小要求：
364: 
365: ```
366: POST /rpc             → 解析 JSON-RPC，分发 music.ping / music.list / music.streamUrl
367: GET  /stream/{id}?token=… → 返回音频字节流（务必支持 Range）
368: ```
369: 
370: 若要支持按专辑 / 艺术家浏览，再实现三个可选方法：`music.listAlbums`、
371: `music.listArtists`、`music.listSongs`。
372: 
373: > 实现服务端时务必支持 **HTTP Range 请求**，否则进度条拖动与流式播放体验会受影响。
